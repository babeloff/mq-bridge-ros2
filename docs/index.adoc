= mq-bridge-ros2 documentation
:toc: left
:icons: font

`mq-bridge-ros2` is an input and output endpoint for https://github.com/marcomq/mq-bridge[mq-bridge].
It connects routes to ROS 2 topics through https://github.com/ros2-rust/ros2_rust[`rclrs`].

The endpoint is distributed as one compiled library.
You can link it directly into a Rust program,
load it as a plugin in an mq-bridge host,
or use it through the Python and npm packages.

This documentation focuses on using the endpoint as a plugin.
That is where loading, packaging, ROS 2 discovery, and delivery behavior affect a route.

The project follows the https://github.com/marcomq/mq-bridge/tree/main/examples/plugin-template[mq-bridge plugin template].
Its endpoint implementation uses `rclrs` and ROS 2 dynamic messages.

== Recommended installation: Pixi and conda packages

The usual way to run the endpoint is to install `mq-bridge` and `mq-bridge-ros2`
as conda packages in the same https://pixi.sh/[Pixi] environment.
The `mq-bridge-ros2` package brings the ROS 2 runtime packages required by its selected distribution,
and its plugin library is installed where mq-bridge can discover it.

For example,
this environment selects the Jazzy build of the endpoint:

[source,toml]
----
[workspace]
channels = [
    "https://program-forge.invalid",
    "https://prefix.dev/robostack-jazzy",
    "conda-forge",
]

[dependencies]
mq-bridge = "*"
mq-bridge-ros2 = { version = "*", build = "ros2_jazzy_*" }
----

Create the environment and install its packages with:

[source,console]
----
pixi install
----

The canonical program-forge channel name is resolved through Pixi's mirror configuration.
If that mirror is not already configured,
follow xref:how-to/publish-to-the-registry.adoc[the registry guide] before adding the dependency.
Use `ros2_humble_*` instead when the environment targets Humble.

The endpoint is then available to any mq-bridge route running inside that environment.
There is no separate library path to configure and no Rust build step at runtime.

== Requirements

`rclrs` links against `rcl` and loads message type support libraries from ROS 2.
The ROS 2 environment must be available to build and run the endpoint.

[source,console]
----
source /opt/ros/jazzy/setup.bash
----

You can use the project's Pixi environment instead.
It installs ROS 2 from https://robostack.github.io/[RoboStack] and activates the environment for each task.

[source,console]
----
pixi run test
----

See xref:reference/pixi-tasks.adoc[Pixi tasks] for the available commands.
