= mq-bridge-ros2 documentation
:toc: left
:icons: font

A ROS 2 input and output endpoint for https://github.com/marcomq/mq-bridge[mq-bridge], built on https://github.com/ros2-rust/ros2_rust[`rclrs`].

The same compiled library is used three ways:
linked directly into a Rust program, loaded as a native plugin by any mq-bridge host, and shipped inside the Python and npm packages that hand it to that same loader.
Most of this documentation is about that third life — operating the endpoint as a *plugin* — because that is where the parts a route author cannot see live.

This project is derived from https://github.com/marcomq/mq-bridge-pulsar[mq-bridge-pulsar].
Its factory, plugin export, error classification and batch-commit structure are that project's, with Apache Pulsar replaced by ROS 2.

== How this documentation is organised

It follows https://diataxis.fr/[Diátaxis], which separates four things that are usually mixed together and are hard to write well when they are.
Each section answers one question, so start with the one matching what you actually need.

[cols="1,2,3", options="header"]
|===
| Section | Answers | Read it when

| xref:tutorials/first-ros2-route.adoc[Tutorials]
| "Take me through it."
| You have never run this endpoint and want a working route in front of you.

| xref:how-to/load-the-plugin-in-a-host.adoc[How-to guides]
| "How do I achieve this?"
| You know what you want and need the steps for that one job.

| xref:reference/configuration.adoc[Reference]
| "What exactly does this accept?"
| You are writing configuration and need the precise, complete answer.

|===

== Before anything else

`rclrs` links `rcl` and loads message type support libraries from a ROS installation.
There is no build and no test run without one, not even for the unit tests, whose binary would fail to load.

[source,console]
----
source /opt/ros/jazzy/setup.bash
----

Or use this project's pixi environment, which installs ROS 2 from https://robostack.github.io/[RoboStack] and activates it for every task:

[source,console]
----
pixi run test
----

See xref:reference/pixi-tasks.adoc[Pixi tasks] for the full set.
